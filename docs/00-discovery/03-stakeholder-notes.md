# ステークホルダー観察

関係者の役割・関心・期待・成功基準を整理する。
ここでは ID を採番しない（人物そのものを ID 化しない）。

## ステークホルダー一覧

| 役割 | 個人 / 部署 | 関心領域 | 期待 | 成功基準 (彼らから見た) | 連絡手段 |
| --- | --- | --- | --- | --- | --- |
| プロダクトオーナー（学習プロジェクト主） | ユーザ本人 | 全体方針・スコープ・学習目標 | 各フェーズの成果物が技術学習にも繋がる形で揃う | 本リポジトリのドキュメントとコードが教材として読める | 直接対話 |
| 開発リード（Claude） | Claude Code | 設計駆動ハーネスに沿った実装 | 各フェーズの ID トレーサビリティが保たれる | `npx tsx scripts/validate-traceability.ts` が errors=0 | このリポジトリ |
| 一般市民（投稿者） | 想定ペルソナ | 提案・報告・申請、相談、公開範囲の自己決定 | 安心して投稿でき、公開判断が透明 | 自分の投稿のステータスと判断理由が見える | (アプリ内) |
| レビュアー | 想定ペルソナ | 投稿内容の判定、判断理由の記録 | 効率的にレビューでき、判断根拠が残る | レビュー待ち一覧／詳細／判断アクションが滞りなく回る | (アプリ内) |
| 管理者 | 想定ペルソナ | 公開範囲、強権操作、運用全般 | 強権操作が記録され、責任が明示される | 自分の操作がすべて AuditLog に残ることが確認できる | (アプリ内) |
| 監査担当 (auditor) | 想定ペルソナ | 説明責任、内部統制 | 監査ログを **読むだけ** ができる、改竄不能 | 任意の操作の経緯を後から再構成できる | (アプリ内) |
| 法務・コンプライアンス | 想定ペルソナ | 個人情報保護、誹謗中傷リスク | 投稿時の同意・公開前レビューが運用されている | 同意ログ・判断ログが残っている | (アプリ外) |
| カスタマーサポート（仮） | 未割当 | 投稿者の問い合わせ対応 | 投稿のステータスを参照できる | (MVP では対象外) | (MVP では未整備) |

> 本プロジェクトは学習目的の単独開発であり、上記のうち「想定ペルソナ」は実在の関係者ではなく
> ユーザストーリ設計のための仮想ロールである。実在ステークホルダーはプロダクトオーナーと
> 開発リード（Claude）の 2 者のみ。

## 観察メモ

### プロダクトオーナー（学習者本人）
- インタビュー日: 2026-05-03（プロンプトとして提示）
- 主な関心:
  - TanStack Start + Cloudflare Workers の実用パターン習得
  - 認証・認可・監査ログを **設計レベルで** 整理する経験
  - 技術倫理・プライバシーを後付けでなく要件として扱う
- 譲れない点:
  - 段階的に進める（要件 → 設計 → 実装）
  - server function 側で認可
  - 監査ログを設計に組み込む
- 妥協できる点:
  - 初期の DB はモック / インメモリで可
  - メール通知は将来
  - AI 自動分類は将来
- 関連 IDEA / PROB:
  - IDEA-007: TanStack Start + Cloudflare Workers アーキテクチャ採用
  - PROB-001: 公開前レビュー無しに投稿が公開されてしまうリスク

### 想定ペルソナ：一般市民・投稿者
- 想定:
  - スマートフォンから投稿することが多い
  - センシティブな相談をしたいケースもある
  - 自分の投稿のステータスを後から見たい
- 主な関心:
  - 投稿が「ちゃんと届いている」ことの可視化
  - 個人情報を書いた場合のリスク表示
  - 公開範囲の自己決定
- 関連 IDEA / PROB:
  - IDEA-003: 公開範囲（Visibility）の投稿者制御
  - PROB-006: 投稿者が公開範囲をコントロールできない

### 想定ペルソナ：レビュアー
- 想定:
  - 自治体職員 / コミュニティ運営担当
  - 1 日のうち決まった時間にまとめてレビュー
- 主な関心:
  - 効率的に未処理を捌く
  - 「判断理由必須」のフォームが負担になりすぎない設計
- 関連 IDEA / PROB:
  - IDEA-002: 公開前レビュー・承認フロー
  - PROB-003: レビュー判断の理由が記録されず説明責任が果たせない

### 想定ペルソナ：管理者
- 主な関心:
  - 公開範囲の事後変更
  - 重大トラブル時の取り下げ
  - 自分の操作が監査されることを **当然と受け入れる**
- 関連 IDEA / PROB:
  - IDEA-004: 役割分離（user / reviewer / admin / auditor / guest）
  - PROB-004: 管理者操作の追跡可能性がない

### 想定ペルソナ：監査担当 (auditor)
- 主な関心:
  - 監査ログ閲覧の権限のみで、書き込み権限は持たない
  - 任意の `proposal id` から関連操作を一覧できる
- 関連 IDEA / PROB:
  - IDEA-005: 管理者操作の監査ログ
  - PROB-004: 管理者操作の追跡可能性がない
