# システム全体像

## 目的

このシステムが解決する課題と、達成したい価値を 3〜5 行で記述する。
要件定義の「概要」と一致させ、過不足なく書くこと。

## ユースケース一覧 (UC-XXX)

各 UC は `<アクター> が <目的> を達成する` の形で短く書く。
詳細フローは詳細設計（画面・API）で記述する。

| ID | アクター | 目的 | 関連 REQ |
| --- | --- | --- | --- |
| UC-001 | 一般ユーザ | ログインしてダッシュボードを開く | REQ-001 |

## ユースケース別の概要

### UC-001 — ログインしてダッシュボードを開く
- 入力: メールアドレス、パスワード
- 主シナリオ:
  1. ログイン画面でメール + パスワードを入力する
  2. 認証成功でダッシュボードへ遷移する
- 例外シナリオ:
  - 資格情報誤り → 同一画面でエラー表示
  - レート超過 → 一定時間操作不能
- 関連 SCR / API: SCR-001 / API-001
- 参照: REQ-001

> ### UC-XXX — <目的>
> - 入力:
> - 主シナリオ:
> - 例外シナリオ:
> - 関連 SCR / API:
> - 参照: REQ-XXX
> ```
