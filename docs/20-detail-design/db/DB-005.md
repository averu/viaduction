# DB-005 — policy_agreements（プライバシーポリシー同意ログ）

## 概要

投稿提出 (UC-002 / REQ-002) 時にユーザがプライバシーポリシー（REQ-014）に同意した事実を記録するエンティティ。`user_id / proposal_id / agreed_at / policy_version` を必須フィールドとする (`BR-GUARD-02`)。Q-018 暫定方針「再提出時は新規生成しない」に従い、**1 proposal につき最大 1 レコード** を制約として持つ。

## カラム

| カラム名 | 型 | null | デフォルト | PK/FK/UK | 説明 |
| --- | --- | --- | --- | --- | --- |
| `id` | text | no | — | PK | 同意レコード ID。`crypto.randomUUID()` で生成（UUID v7 相当、Workers 互換）。最大長 36 文字（標準 UUID 表現）。 |
| `user_id` | text | no | — | FK → `users(id)` | 同意したユーザの識別子。`guest` は提出操作不可のため `user` 以上のロールに限定（REQ-002 / `BR-AUTHZ-01`）。 |
| `proposal_id` | text | no | — | FK → `proposals(id)` UK | 同意の対象 proposal。**1 proposal = 1 PolicyAgreement**（Q-018 暫定）。 |
| `policy_version` | text | no | — | — | 同意したポリシー文書のバージョン識別子。Q-008 確定までの暫定値は `mvp-initial`。形式は API-018 のレスポンス `policy_version` と整合（REQ-014）。最大長 64 文字。 |
| `agreed_at` | integer | no | — | — | 同意時刻（Unix epoch millis）。提出 server function (API-002) の成功時にサーバ側で記録。 |

> **型の方針（NFR-002 と整合）**: SQLite 互換の `text` / `integer` のみ。タイムスタンプは Unix epoch millis。

## インデックス

| 名前 | カラム | 種別 | 用途 |
| --- | --- | --- | --- |
| `pk_policy_agreements` | `(id)` | primary | 主キー検索 |
| `ux_policy_agreements_proposal` | `(proposal_id)` | unique | **1 proposal = 1 同意**（Q-018 暫定方針）。`findByProposalId` の高速化と重複生成の防止を兼ねる。 |
| `ix_policy_agreements_user_agreed_at` | `(user_id, agreed_at DESC)` | non-unique | ユーザごとの同意履歴取得（将来的な「ユーザ別同意履歴」画面用、MVP では未使用だが index を先行設置） |

> 注記: `ix_policy_agreements_user_agreed_at` は MVP では参照する loader が無い（API-018 はポリシー文書取得で本テーブルを read しない）。将来「自分の同意履歴」画面（IDEA-008 派生）が起票された場合に活用するための先行 index。MVP のテーブル規模では追加コストが小さいと判断し、Phase 5 でドロップ可否を再評価する。

## 不変条件

1. **1 proposal = 最大 1 レコード**: `ux_policy_agreements_proposal` の UNIQUE 制約で **DB 層で強制**。Q-018 暫定方針「再提出時は再生成しない」と整合。
   - Q-018 が「再取得必須」で確定した場合、本制約は解除し `(proposal_id, policy_version)` の複合 UNIQUE などに変更する（マイグレーション要、後段「マイグレーション方針」を参照）。
2. **append-only ではない（が delete もしない）**: `BR-GUARD-02` により提出成功時に 1 件生成するのみ。`UPDATE` / `DELETE` は MVP では行わない。Repository の export は `create` / `findByProposalId` のみとし、`update` / `delete` は export しない（`BD-DATA` の Repository 表と整合、アプリ層強制）。
3. **policy_version の整合**: `policy_version` は API-018 (`/policies/privacy`) のレスポンスで返却する `policy_version` と同一形式。MVP では `mvp-initial` リテラルを使用し、Q-008 確定後にバージョン番号体系（例: SemVer / 日付ベース）を導入する。
4. **生成タイミングの限定**: `INSERT` は API-002 (`submit`) の成功時のみ（`BR-GUARD-02`）。API-009 (`resubmit`) では `INSERT` しない（Q-018 暫定）。アプリ層で API ごとに repository 呼び出しを分け、`create` を呼ぶ箇所が API-002 のみであることをコードレビューで確認する。
5. **FK 整合**: `user_id` は `users.id` に存在、`proposal_id` は `proposals.id` に存在し、かつ `proposals.author_id == user_id` を満たす（同意したユーザ＝投稿者本人、REQ-002）。後者の整合はアプリ層で `assertOwner` チェック後に `create` を呼ぶことで担保（DB 層 CHECK では多テーブル参照を表現できないため）。

## 関連 API

| API | 操作 | 備考 |
| --- | --- | --- |
| API-002 (`submit`) | write (INSERT) | 提出成功時に 1 件 INSERT。倫理ガード 3 種 (`BR-GUARD-01`) と PolicyAgreement 同意 (`BR-GUARD-02`) を server-side 検証してから書き込む。 |
| API-002 (`submit`) | read (UNIQUE 制約検査) | 同一 `proposal_id` の既存レコードがある場合は `ux_policy_agreements_proposal` 違反で `INSERT` 失敗 → アプリ層で `409 CONFLICT` または `422 BUSINESS_RULE_VIOLATION` に正規化（API 詳細設計で確定）。 |
| API-009 (`resubmit`) | — | Q-018 暫定方針により **INSERT しない**。既存レコードを継続適用する（参照のみ可、`findByProposalId`）。 |
| API-018 (`/policies/{posting,privacy}`) | — | 本テーブルは read しない。`policy_version` の整合性は「ポリシー文書側が真の値、本テーブルは同意時のスナップショット」という関係。 |

## マイグレーション方針

### 追加
- カラム追加は **`null` 許容で追加 → バックフィル → `not null` 化** の 3 ステップ。
- 例: 将来 `agreed_locale`（同意時の表示言語）を追加する場合、既存レコードを `ja-JP` でバックフィル。

### Q-018 確定時の変更（再提出時に再取得必須となった場合）
- `ux_policy_agreements_proposal` を **削除**（1 proposal = 複数同意を許容）。
- 代わりに `(proposal_id, policy_version, agreed_at)` を `findByProposalId` の戻り値として「最新を返す」セマンティクスに変更（Repository 詳細設計で確定）。
- 関連 AC: REQ-006 / REQ-013 の AC（再提出時の policy_agreement 継続適用）を更新。

### MVP DDL（D1 移行時、SQLite 互換）

```sql
CREATE TABLE policy_agreements (
  id              TEXT NOT NULL PRIMARY KEY,
  user_id         TEXT NOT NULL REFERENCES users(id),
  proposal_id     TEXT NOT NULL REFERENCES proposals(id),
  policy_version  TEXT NOT NULL,
  agreed_at       INTEGER NOT NULL
);

CREATE UNIQUE INDEX ux_policy_agreements_proposal
  ON policy_agreements(proposal_id);

CREATE INDEX ix_policy_agreements_user_agreed_at
  ON policy_agreements(user_id, agreed_at DESC);
```
