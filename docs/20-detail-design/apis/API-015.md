# API-015 — get reviewProposal（レビュー詳細 loader）

## 概要

`reviewer` または `admin` が `submitted` / `in_review` の提案詳細と関連 AuditLog 履歴を取得する loader（UC-003〜006）。担当開始 / 判定操作の前段で呼ばれる。reviewer は `private` 投稿に到達不可（Q-016 暫定 → 404）。

## エンドポイント

```
GET /v1/review/proposals/{id}
```

## 認可

- **レベル**: `authenticated`
- **必要ロール**: `reviewer` または `admin`
- **リソース所有者一致**: 不要（ただし reviewer の `private` アクセスは 404）
- **CSRF 検証**: GET のため不要
- **レート制限**: MVP 対象外（Q-013 暫定）
- **公開バイパス**: 対象外

## リクエスト

### パスパラメータ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string (uuid v7) | yes | 対象 proposal の ID |

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Cookie` | yes | 認証 cookie（reviewer / admin） |

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `proposal_id` | string (uuid v7) | yes | ID |
| `title` | string | yes | タイトル |
| `body` | string | yes | 本文 |
| `visibility` | string | yes | `private`（admin のみ）/ `internal` / `public` |
| `status` | string | yes | `submitted` または `in_review` のみ（その他は 422 ではなく 404 で隠蔽） |
| `author_id` | string (uuid v7) | yes | 投稿者 ID |
| `assignee_id` | string \| null | no | `in_review` の場合は担当者 |
| `submitted_at` | integer | yes | 提出時刻 |
| `updated_at` | integer | yes | 最終更新時刻 |
| `version` | integer | yes | 楽観ロック用 |
| `current_policy_agreement_id` | string \| null | no | 同意レコード ID |
| `policy_version` | string | yes | 同意したポリシーバージョン（DB-005 の policy_version） |
| `audit_log_history[]` | array | yes | 当該 proposal の AuditLog 履歴（時系列順）。表示対象 action は `submit` / `return` / `resubmit` のみ（レビュー判定の前段として「過去の差し戻し履歴」を提示） |
| `audit_log_history[].audit_log_id` | string (uuid v7) | yes | エントリ ID |
| `audit_log_history[].action` | string | yes | `submit` / `return` / `resubmit` |
| `audit_log_history[].actor_id` | string (uuid v7) | yes | 操作実行者 |
| `audit_log_history[].actor_role` | string | yes | スナップショット role |
| `audit_log_history[].before_status` / `after_status` | string | yes | 遷移前後 |
| `audit_log_history[].reason` | string \| null | no | reason テキスト |
| `audit_log_history[].created_at` | integer | yes | 記録時刻 |

> `audit_log_history` の表示対象を `submit` / `return` / `resubmit` に絞る理由（m-10 整理）: レビュアーの判断補助として「**過去の差し戻し履歴**」を強調するため、本詳細画面では `submit` / `return` / `resubmit` の往復のみを表示。`start_review` を含めない理由は「判定補助としての差し戻し履歴を強調するため」（`start_review` は assignee_id で表現済み、status バッジでも表現済みのため冗長）。`approve` / `reject` も終端状態を示すため本画面到達時には対象 status から外れている（API-015 は `submitted` / `in_review` のみ返す）。完全な AuditLog 閲覧は API-016 を経由。

### 4xx / 5xx

| ステータス | アプリコード | 状況 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | id 形式不正 |
| 401 | `UNAUTHENTICATED` | guest |
| 404 | `NOT_FOUND` | proposal 不存在 / role 不足 / `private` を reviewer が要求（Q-016 暫定）/ `status` が `submitted` / `in_review` 以外 |
| 500 | `INTERNAL_ERROR` | 想定外 |

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-003 (proposals) | read | 主キー検索 + visibility / status / role の組合せ検証 |
| DB-004 (audit_logs) | read | `WHERE target_proposal_id=? AND action IN ('submit','return','resubmit') ORDER BY created_at ASC`。`ix_audit_logs_target_proposal` を使用 |
| DB-006 (users) | read | viewer の role 確認 |

## 認可拒否時の挙動

| 拒否シナリオ | HTTP | logger `403_reason` |
| --- | --- | --- |
| cookie なし | 401 | `not_authenticated` |
| role が `user` のみ / `auditor` | 404 | `insufficient_role` |
| reviewer が `private` を要求（Q-016 暫定） | 404 | `insufficient_role` |
| `status` が `submitted` / `in_review` 以外 | 404 | `status_not_reviewable` |

副作用なし。
