# API-008 — withdraw（取り下げ server function、admin 専権）

## 概要

`admin` のみが `published` の提案を `withdrawn` に遷移させる mutation。reason 必須（`BR-PUBLISH-03`）。`approved → withdrawn` は不可（`published` 経由のみ、REQ-005）。本文は一般閲覧経路から非表示になるが、AuditLog から `(published_at, withdrawn_at)` ペアが追跡可能。

## エンドポイント

```
POST /v1/proposals/{id}/withdraw
```

## 認可

- **レベル**: `authenticated`
- **必要ロール**: `admin` のみ
- **リソース所有者一致**: 不要
- **CSRF 検証**: Origin / Sec-Fetch-Site=same-origin（NFR-006）
- **レート制限**: MVP 対象外（Q-013 暫定）

## リクエスト

### パスパラメータ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string (uuid v7) | yes | `status='published'` 前提 |

### ボディ

```json
{
  "reason": "公開後に申立があり該当箇所の確認のため一時取り下げ",
  "expected_version": 4
}
```

#### スキーマ

| フィールド | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `reason` | string | **yes** | 1〜4000 文字、trim 後 1 文字以上（`BR-PUBLISH-03`） |
| `expected_version` | integer | yes | CAS 用 |

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Cookie` | yes | 認証 cookie（admin） |
| `Origin` | yes | 同一オリジン |
| `Sec-Fetch-Site` | yes | `same-origin` |

## レスポンス

### 200 OK

```json
{
  "proposal_id": "01HXYZ...",
  "status": "withdrawn",
  "withdrawn_at": 1746360000000,
  "published_at": 1746000000000,
  "version": 5,
  "audit_log_id": "01HXYZ-al..."
}
```

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `proposal_id` | string | yes | 対象 ID |
| `status` | string | yes | `"withdrawn"` |
| `withdrawn_at` | integer | yes | 取り下げ時刻 |
| `published_at` | integer | yes | 公開時刻（保持される） |
| `version` | integer | yes | +1 |
| `audit_log_id` | string | yes | append された AuditLog ID |

### 4xx / 5xx

| ステータス | アプリコード | 状況 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | reason 空 / 文字数超過 |
| 401 | `UNAUTHENTICATED` | cookie なし |
| 404 | `NOT_FOUND` | role が admin でない / proposal 不存在 |
| 409 | `CONFLICT` | 楽観ロック失敗 |
| 422 | `BUSINESS_RULE_VIOLATION` | `status != 'published'`（特に `approved` からの直接 withdraw を拒否、REQ-005） |
| 500 | `INTERNAL_ERROR` | 想定外 |

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-003 (proposals) | write (UPDATE, CAS) | `WHERE id=? AND version=expected_version AND status='published'` で `status='withdrawn'`、`withdrawn_at=now`、`updated_at=now`、`version+1`。`published_at` は保持（REQ-005） |
| DB-004 (audit_logs) | append (INSERT) | reason 必須 |
| DB-006 (users) | read | role 確認 |

## AuditLog 書き込み

| フィールド | 値 |
| --- | --- |
| `action` | `withdraw` |
| `actor_id` | `viewer.user_id` |
| `actor_role` | スナップショット（`admin` を含む） |
| `target_proposal_id` | パス引数 |
| `before_status` | `published` |
| `after_status` | `withdrawn` |
| `reason` | NOT NULL |
| `policy_agreement_id` | NULL |
| `created_at` | `now()` |

`reason` 必須要否: **必須**（`BR-PUBLISH-03`）。

## 認可拒否時の挙動

| 拒否シナリオ | HTTP | logger `403_reason` |
| --- | --- | --- |
| cookie なし | 401 | `not_authenticated` |
| role が `admin` を含まない | 404 | `insufficient_role` |
| Origin 不一致 (CSRF, B-2) | **403** | `cross_site` |

副作用なし。

## バリデーション規約

- Zod（暫定）
- 順序: API-007 と同等（reason 必須を 400 で先に弾く点が異なる）

API-007 と同セット。

## 後続挙動の注記

- `withdrawn` 後、API-010 / API-011 / API-013 はいずれも `withdrawn` を loader 側でフィルタして 404 を返す（REQ-005 AC）。
- AuditLog 経路（API-016 / API-017）からは `before_status=published` / `after_status=withdrawn` のエントリ + 既存 `publish` エントリの突合で公開期間が観測可能。
