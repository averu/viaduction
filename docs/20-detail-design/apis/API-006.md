# API-006 — reject（却下 server function）

## 概要

担当中の `reviewer` または `admin` が `in_review` の提案を `rejected`（終端）に遷移させる mutation。reason 必須（`BR-REVIEW-01`）。`rejected` は終端で再提出不可。

## エンドポイント

```
POST /v1/proposals/{id}/reject
```

## 認可

- **レベル**: `authenticated`
- **必要ロール**: `reviewer` または `admin`
- **リソース所有者一致**: **不要 (B-3 撤回)**。reviewer / admin であれば assignee に関わらず判定可（API-004 と同じ方針、要件 REQ-003 / BR-REVIEW-* に従う）
- **CSRF 検証**: Origin / Sec-Fetch-Site=same-origin（NFR-006）
- **レート制限**: MVP 対象外（Q-013 暫定）

## リクエスト

### パスパラメータ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string (uuid v7) | yes | `status='in_review'` 前提 |

### ボディ

```json
{
  "reason": "本サービスの取扱範囲外（個人間の民事紛争）のため受理しません",
  "expected_version": 2
}
```

#### スキーマ

| フィールド | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `reason` | string | **yes** | 1〜4000 文字 |
| `expected_version` | integer | yes | CAS 用 |

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Cookie` | yes | 認証 cookie |
| `Origin` | yes | 同一オリジン |
| `Sec-Fetch-Site` | yes | `same-origin` |

## レスポンス

### 200 OK

```json
{
  "proposal_id": "01HXYZ...",
  "status": "rejected",
  "version": 3,
  "audit_log_id": "01HXYZ-al..."
}
```

#### スキーマ

API-004 と同形（`status` のみ `"rejected"`）。

### 4xx / 5xx

API-004 と同セット。

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-003 (proposals) | write (UPDATE, CAS) | `WHERE id=? AND version=expected_version AND status='in_review'` で `status='rejected'`、`assignee_id=NULL`、`updated_at=now`、`version+1`。**終端**（後続遷移なし）。**B-3 撤回**: assignee_id 一致条件は CAS から削除 |
| DB-004 (audit_logs) | append (INSERT) | reason 必須 |
| DB-006 (users) | read | role 確認 |

## AuditLog 書き込み

| フィールド | 値 |
| --- | --- |
| `action` | `reject` |
| `actor_id` | `viewer.user_id` |
| `actor_role` | スナップショット |
| `target_proposal_id` | パス引数 |
| `before_status` | `in_review` |
| `after_status` | `rejected` |
| `reason` | NOT NULL |
| `policy_agreement_id` | NULL |
| `created_at` | `now()` |

`reason` 必須要否: **必須**。

## 認可拒否時の挙動

API-004 と同じパターン（`not_authenticated` / `insufficient_role` / `cross_site`）。**B-3 確定**: `assignee_id != viewer.user_id` の事由は撤回（assignee 一致は要求しない）。**B-2 確定**: CSRF 違反は **403 CSRF_DENIED**。副作用なし。

## バリデーション規約

API-004 と同等。
