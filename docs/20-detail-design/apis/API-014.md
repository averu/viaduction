# API-014 — list reviewInbox（レビュー待ち一覧 loader）

## 概要

`reviewer` または `admin` が `submitted` / `in_review` の提案を横断一覧する loader（REQ-009 / UC-012）。reviewer は `private` を除外（Q-016 暫定）、admin は全件閲覧可。`user` / `auditor` は 404、`guest` は 401。

## エンドポイント

```
GET /v1/review/queue
```

## 認可

- **レベル**: `authenticated`
- **必要ロール**: `reviewer` または `admin`
- **リソース所有者一致**: 不要（reviewer は他人の投稿をレビューする）
- **CSRF 検証**: GET のため不要
- **レート制限**: MVP 対象外（Q-013 暫定）
- **公開バイパス**: 対象外

## リクエスト

### パスパラメータ

なし。

### クエリパラメータ

| 名前 | 型 | 必須 | デフォルト | 説明 |
| --- | --- | --- | --- | --- |
| `cursor` | string | no | null | カーソル |
| `limit` | integer | no | 20 | 1〜100 |
| `status` | string | no | (`submitted` + `in_review` 両方) | `submitted` または `in_review` のいずれかでフィルタ可 |

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Cookie` | yes | 認証 cookie（reviewer / admin） |

## レスポンス

### 200 OK

```json
{
  "items": [
    {
      "proposal_id": "01HXYZ...",
      "title": "○○交差点の歩道整備に関する提案",
      "status": "submitted",
      "visibility": "internal",
      "author_id": "01HXYZ-user-a1",
      "submitted_at": 1746000000000,
      "updated_at": 1746000000000,
      "assignee_id": null,
      "version": 1
    }
  ],
  "next_cursor": null,
  "has_more": false
}
```

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `items[].proposal_id` | string (uuid v7) | yes | ID |
| `items[].title` | string | yes | タイトル |
| `items[].status` | string | yes | `submitted` または `in_review` |
| `items[].visibility` | string | yes | `public` / `internal`（reviewer）/ + `private`（admin のみ） |
| `items[].author_id` | string (uuid v7) | yes | 投稿者 ID |
| `items[].submitted_at` | integer | yes | 提出時刻 |
| `items[].updated_at` | integer | yes | 最終更新時刻 |
| `items[].assignee_id` | string \| null | no | `in_review` の場合は担当者 ID |
| `items[].version` | integer | yes | 楽観ロック用 |
| `next_cursor` | string \| null | no | 次ページ用 |
| `has_more` | boolean | yes | 次ページの有無 |

> 並び順: **`submitted_at ASC`（確定）**。古いものから処理する運用を優先（M-11 確定、REQ-009 §Open Questions の「並び順」項目に対する詳細設計時点での確定対応）。`updated_at DESC` 等の代替案は Phase 6 入口で UX レビュー時に再評価可能だが、現時点では `submitted_at ASC` で実装を進める。

### 4xx / 5xx

| ステータス | アプリコード | 状況 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | クエリ不正 |
| 401 | `UNAUTHENTICATED` | guest |
| 404 | `NOT_FOUND` | role が `reviewer` / `admin` のいずれでもない（user / auditor）。暫定統一で 404 |
| 500 | `INTERNAL_ERROR` | 想定外 |

## viewer × visibility のフィルタ条件（M-7 確定）

| viewer.role | フィルタ |
| --- | --- |
| `reviewer` | `visibility IN ('public', 'internal')`（`private` を除外、Q-016 暫定） |
| `admin` | `visibility IN ('public', 'internal', 'private')`（**全 visibility を一覧表示可**、レビュー判定対象として明示） |
| `user` / `auditor` / `guest` | 404 / 401（一覧自体に到達不可） |

> **API-010 との差異（M-7 整理）**: 公開投稿一覧 (API-010) では admin であっても `private` を除外するが、本 API（レビュー待ち一覧）では admin のみ `private` を含む。理由: レビューフローは「判定対象としてセンシティブ投稿も明示する」必要があるが、公開閲覧フローは「センシティブ投稿を一般 admin の公開ナビゲーションに混ぜない」設計のため。

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-003 (proposals) | read | `WHERE status IN ('submitted','in_review') [AND visibility != 'private' if role=reviewer]` + `ORDER BY submitted_at ASC` + `LIMIT limit`。`ix_proposals_status_visibility` および `ix_proposals_status_updated_at` を使用 |
| DB-006 (users) | read | viewer の role 確認 |

## 認可拒否時の挙動

| 拒否シナリオ | HTTP | logger `403_reason` |
| --- | --- | --- |
| cookie なし | 401 | `not_authenticated` |
| role が `user` のみ / `auditor` | 404 | `insufficient_role` |

副作用なし。
