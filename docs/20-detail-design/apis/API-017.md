# API-017 — get auditLog（監査ログ詳細 loader）

## 概要

`auditor` または `admin` が AuditLog エントリ 1 件のメタ情報（reason 本体含む）を取得する loader（REQ-012 / UC-015）。auditor が target proposal 本文へ遷移する経路は提供しない（Q-016 暫定: 本文不到達。target proposal_id を返すが loader は API-011 を経由し、auditor が `private` を要求すると 404）。

## エンドポイント

```
GET /v1/audit/logs/{id}
```

## 認可

- **レベル**: `authenticated`
- **必要ロール**: `auditor` または `admin`
- **リソース所有者一致**: 不要
- **CSRF 検証**: GET のため不要
- **レート制限**: MVP 対象外（Q-013 暫定）
- **公開バイパス**: 対象外

## リクエスト

### パスパラメータ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string (uuid v7) | yes | AuditLog エントリ ID |

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Cookie` | yes | 認証 cookie（auditor / admin） |

## レスポンス

### 200 OK

```json
{
  "audit_log_id": "01HXYZ-al-1",
  "actor_id": "01HXYZ-user-r1",
  "actor_role": "reviewer",
  "action": "return",
  "target_proposal_id": "01HXYZ-p1",
  "before_status": "in_review",
  "after_status": "returned",
  "before_visibility": null,
  "after_visibility": null,
  "reason": "本文に個人名が含まれている可能性があるため、該当箇所の修正をお願いします",
  "policy_agreement_id": null,
  "created_at": 1746360000000
}
```

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `audit_log_id` | string (uuid v7) | yes | エントリ ID |
| `actor_id` | string (uuid v7) | yes | 操作実行者 |
| `actor_role` | string | yes | スナップショット role |
| `action` | string | yes | DB-004 の `action` 値 |
| `target_proposal_id` | string (uuid v7) | yes | 対象 proposal |
| `before_status` / `after_status` | string \| null | no | 遷移前後 |
| `before_visibility` / `after_visibility` | string \| null | no | MVP では常に NULL |
| `reason` | string \| null | no | reason 本体（本詳細 API では返す。一覧 API-016 では `reason_present` のみ） |
| `policy_agreement_id` | string \| null | no | submit / resubmit のみ |
| `created_at` | integer | yes | 記録時刻 |

> `target_proposal_id` を含むが、本文取得は別 API（API-011）を経由。auditor が `private` を要求すると API-011 側で 404 を返す（Q-016 暫定）。

### 4xx / 5xx

| ステータス | アプリコード | 状況 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | id 形式不正 |
| 401 | `UNAUTHENTICATED` | guest |
| 404 | `NOT_FOUND` | エントリ不存在 / role 不足 |
| 500 | `INTERNAL_ERROR` | 想定外 |

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-004 (audit_logs) | read | 主キー検索（`pk_audit_logs`） |
| DB-006 (users) | read | viewer の role 確認 |

> AuditLog repository の `findById(id)` を呼ぶ。`update` / `delete` は呼ばない（NFR-004）。

## 認可拒否時の挙動

| 拒否シナリオ | HTTP | logger `403_reason` |
| --- | --- | --- |
| cookie なし | 401 | `not_authenticated` |
| role が `user` のみ / `reviewer` | 404 | `insufficient_role` |

副作用なし。

## バリデーション規約

- Zod（暫定）
- `id`: UUID v7 形式

## エラーコード

| HTTP | コード | 用途 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | id 形式不正 |
| 401 | `UNAUTHENTICATED` | guest |
| 404 | `NOT_FOUND` | role 不足 / 不存在 |
| 500 | `INTERNAL_ERROR` | 想定外 |

## ログへの reason 出力禁止（NFR-005）

- 本 API のレスポンスには reason 本体を含むが、**logger には出力しない**。logger には `audit_log_id` のみを記録し、reason 内容を追跡したい場合は本 API のレスポンスから取得する設計（NFR-005 / NFR-007 と整合）。
