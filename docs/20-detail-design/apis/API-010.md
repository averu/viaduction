# API-010 — list publishedProposals（公開投稿一覧 loader）

## 概要

`status='published'` の提案一覧を viewer ロール × visibility のマトリクスでフィルタして返す loader。`withdrawn` は除外（REQ-005 AC との整合）。`viewer === 'guest'` は公開バイパス対象として `visibility='public'` のみを返す（基本設計の暫定確定方針）。

## エンドポイント

```
GET /v1/proposals
```

> 注記: TanStack Start の route loader として実装（route: `/`）。本詳細設計では JSON API としての URL 表現も併記する。

## 認可

- **レベル**: `mixed`（`guest` 経路は公開バイパス、`user` 以上は `authorize()` 経由）
- **公開バイパス**: `viewer.role === 'guest'`（cookie なし or 許可リスト外）の場合は authorize ヘルパーをスキップし、内部で `filter = visibility = 'public'` を適用
- **必要ロール**: なし（全ロールが呼び出し可能、フィルタ結果が変わるだけ）
- **CSRF 検証**: GET のため不要（読み取り）
- **レート制限**: MVP 対象外（Q-013 暫定）

## リクエスト

### パスパラメータ

なし。

### クエリパラメータ

| 名前 | 型 | 必須 | デフォルト | 説明 |
| --- | --- | --- | --- | --- |
| `cursor` | string | no | null | カーソル（前ページ末尾の `published_at` を base64 エンコードした不透明文字列、暫定形式） |
| `limit` | integer | no | 20 | 1 ページあたりの件数。1〜100 の範囲、超過は 400 |

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Cookie` | no | 任意。あれば authorize、無ければ guest |

### ボディ

なし（GET）。

## レスポンス

### 200 OK

```json
{
  "items": [
    {
      "proposal_id": "01HXYZ...",
      "title": "○○交差点の歩道整備に関する提案",
      "visibility": "public",
      "author_id": "01HXYZ-user-a1",
      "published_at": 1746000000000,
      "updated_at": 1746360000000
    }
  ],
  "next_cursor": "eyJwdWJsaXNoZWRfYXQiOjE3NDYwMDAwMDAwMDB9",
  "has_more": true
}
```

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `items[].proposal_id` | string (uuid v7) | yes | 提案 ID |
| `items[].title` | string | yes | タイトル |
| `items[].visibility` | string | yes | `public` / `internal`（guest には `public` のみ） |
| `items[].author_id` | string (uuid v7) | yes | 投稿者 ID |
| `items[].published_at` | integer | yes | 公開時刻 |
| `items[].updated_at` | integer | yes | 最終更新時刻 |
| `next_cursor` | string \| null | no | 次ページ用カーソル。最終ページなら null |
| `has_more` | boolean | yes | 次ページの有無 |

> 本文 `body` は本一覧 API では返さない（一覧表示の負荷低減）。詳細は API-011 で取得。

### 4xx / 5xx

| ステータス | アプリコード | 状況 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | `limit` が範囲外 / `cursor` 形式不正 |
| 500 | `INTERNAL_ERROR` | 想定外 |

> 401 / 404 は本 API では発生しない（公開バイパス + 全ロール許容）。

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-003 (proposals) | read | `WHERE status='published' AND visibility IN (...)`（viewer による）+ `ORDER BY published_at DESC` + `LIMIT limit`。`ix_proposals_status_visibility` および `ix_proposals_status_published_at` を使用 |
| DB-006 (users) | read | viewer が cookie 持参時のみ `findById` で role 確認 |

> **withdrawn は除外**: `status='published'` フィルタにより自動的に除外される（withdrawn は別 status 値）。

## viewer × visibility のフィルタ

| viewer.role | フィルタ |
| --- | --- |
| `guest` | `visibility = 'public'` のみ |
| `user` / `reviewer` / `admin` / `auditor` | `visibility IN ('public', 'internal')` |

> private 投稿は本 API（一覧）には含めない（admin であっても一覧では除外、詳細 API-011 で取得する）。auditor は Q-016 暫定により本文不到達のため、internal までを一覧に含めるが詳細閲覧は AuditLog 経路を経由しない通常 loader（API-011）でのみ可能（auditor も通常 loader からは閲覧可。AuditLog からの遷移は admin のみ）。

## 認可拒否時の挙動

本 API は公開バイパス + 全ロール許容のため、認可拒否は発生しない。ただし以下を logger に記録:
- `viewer_role` / `filter_visibility`（実際に適用された filter）/ `result_count`

## バリデーション規約

- Zod（暫定）
- `limit`: 1〜100 の整数。超過 / 0 / 負数は 400
- `cursor`: 不透明文字列。改竄検知（base64 デコード後の JSON 解析失敗）は 400

## エラーコード

| HTTP | コード | 用途 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | クエリ形式不正 |
| 500 | `INTERNAL_ERROR` | 想定外 |
