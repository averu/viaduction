# API-022 — createDraft（draft 新規作成 server function）

## 概要

ログイン済ユーザが新規 proposal を draft 状態で作成する mutation（B-4 採番）。
**AuditLog 書き込みは行わない**（BR-PROPOSAL-01 の「結果を変える 5 種・8 操作」に含めない、UC-014 対象外）。
本 API は SCR-004（投稿フォーム）/ SCR-005（自分の投稿一覧）の「新規作成」導線で使われる。

## エンドポイント

```
POST /v1/proposals
```

## 認可

- **レベル**: `authenticated`
- **必要ロール**: `user` 以上（`reviewer`, `admin`, `auditor` のいずれもログイン済なら可）。`guest` は **401**
- **リソース所有者**: `author_id` は呼び出し元 viewer の user_id に **server-side で強制的に設定**（リクエストでは受け取らない）
- **CSRF 検証**: Origin / Sec-Fetch-Site=same-origin（NFR-006）。違反時は **403 CSRF_DENIED** + logger `403_reason=cross_site`
- **レート制限**: MVP 対象外（Q-013 暫定）

## リクエスト

### パスパラメータ

なし。

### クエリパラメータ

なし。

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| Cookie | yes | モック認証 cookie（`session_id`、NFR-006）|
| Origin | yes | CSRF 検証（NFR-006）|

### ボディ

```json
{
  "title": "公園のベンチを増やしたい",
  "body": "...",
  "visibility": "public"
}
```

#### スキーマ

| フィールド | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| title | string | yes | 1〜200 文字、空白のみは無効 |
| body | string | yes | 1〜10000 文字、空白のみは無効 |
| visibility | enum (private/internal/public) | yes | DB-003 CHECK 制約と整合 |

## レスポンス

### 201 Created

```json
{
  "proposal_id": "01J...",
  "status": "draft",
  "version": 0,
  "author_id": "u_self",
  "created_at": 1714867200000,
  "updated_at": 1714867200000
}
```

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| proposal_id | string (UUID v7) | yes | サーバ側で `crypto.randomUUID()` 生成 |
| status | "draft" | yes | 固定 |
| version | 0 | yes | 楽観ロック初期値 |
| author_id | string | yes | server-side で viewer.user_id を設定 |
| created_at, updated_at | integer (epoch ms) | yes | |

### 4xx / 5xx

| ステータス | アプリコード | 状況 | logger `403_reason` |
| --- | --- | --- | --- |
| 400 | VALIDATION_ERROR | title / body 空 / 長さ超過 / visibility 不正 | (出力なし) |
| 401 | UNAUTHENTICATED | 未ログイン (guest) | `not_authenticated` |
| 403 | CSRF_DENIED | Origin / Sec-Fetch-Site 不一致 | `cross_site` |
| 500 | INTERNAL_ERROR | サーバ内部エラー | (出力なし) |

## 認可拒否時の挙動

- **HTTP**: 認可違反は 401（guest）のみ。CSRF 違反は **403 CSRF_DENIED**（暫定統一の認可違反 404 とは別概念、B-2）
- **logger**: NFR-007 二段構造。403/401 いずれも `403_reason` フィールドに事由コードを残す

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-003 (proposals) | write (INSERT) | `id=crypto.randomUUID()`, `author_id=viewer.user_id`, `status='draft'`, `version=0`, `assignee_id=null`, `current_policy_agreement_id=null`, タイムスタンプ系は `submitted_at=null` 等 |

**AuditLog 書き込みなし**（BR-PROPOSAL-01 の「結果を変える 5 種・8 操作」に含めない）。draft 段階は実質的に「個人メモ」扱い。

## バリデーション規約

- 入力検証ライブラリ: Zod 暫定（Phase 5 で確定）
- title / body の空白のみチェック: server-side で `.trim().length > 0` 検証
- visibility: `z.enum(['private', 'internal', 'public'])`

## 関連 SCR / API

- SCR-004（投稿フォーム）の「下書き保存」「新規作成」ボタンが本 API を呼ぶ
- 作成後 SCR-006（自分の投稿詳細）に遷移、本文編集は API-023 (updateDraft)、提出は API-002 (submit)
