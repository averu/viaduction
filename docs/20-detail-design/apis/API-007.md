# API-007 — publish（公開 server function、admin 専権）

## 概要

`admin` のみが `approved` の提案を `published` に遷移させる mutation。reviewer は 404（`BR-PUBLISH-01`、admin 専権）。reason は任意（Q-019 暫定）。

## エンドポイント

```
POST /v1/proposals/{id}/publish
```

## 認可

- **レベル**: `authenticated`
- **必要ロール**: `admin` のみ（`reviewer` は 404、`BR-PUBLISH-01`）
- **リソース所有者一致**: 不要（admin は全件公開可）
- **CSRF 検証**: Origin / Sec-Fetch-Site=same-origin（NFR-006）
- **レート制限**: MVP 対象外（Q-013 暫定）

## リクエスト

### パスパラメータ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string (uuid v7) | yes | `status='approved'` 前提 |

### ボディ

```json
{
  "reason": "市民意見として広報誌掲載予定",
  "expected_version": 3
}
```

#### スキーマ

| フィールド | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `reason` | string \| null | no | 任意（Q-019 暫定）。指定する場合は 1〜4000 文字、trim 後 1 文字以上。空文字や空白のみは null として扱うか 400（Phase 5 で確定、暫定: null として記録） |
| `expected_version` | integer | yes | CAS 用 |

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Cookie` | yes | 認証 cookie（admin） |
| `Origin` | yes | 同一オリジン |
| `Sec-Fetch-Site` | yes | `same-origin` |

## レスポンス

### 200 OK

```json
{
  "proposal_id": "01HXYZ...",
  "status": "published",
  "published_at": 1746360000000,
  "version": 4,
  "audit_log_id": "01HXYZ-al..."
}
```

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `proposal_id` | string | yes | 対象 ID |
| `status` | string | yes | `"published"` |
| `published_at` | integer | yes | 公開時刻（Unix epoch millis、DB-003 `published_at` と一致） |
| `version` | integer | yes | +1 |
| `audit_log_id` | string | yes | append された AuditLog ID |

### 4xx / 5xx

| ステータス | アプリコード | 状況 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 文字数超過 / `expected_version` 欠落 |
| 401 | `UNAUTHENTICATED` | cookie なし |
| 404 | `NOT_FOUND` | role が `admin` でない（reviewer / user / auditor / guest）/ proposal 不存在 |
| 409 | `CONFLICT` | 楽観ロック失敗 |
| 422 | `BUSINESS_RULE_VIOLATION` | `status != 'approved'`（draft / submitted / in_review / returned / rejected / published / withdrawn からの publish は不可） |
| 500 | `INTERNAL_ERROR` | 想定外 |

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-003 (proposals) | write (UPDATE, CAS) | `WHERE id=? AND version=expected_version AND status='approved'` で `status='published'`、`published_at=now`、`updated_at=now`、`version+1` |
| DB-004 (audit_logs) | append (INSERT) | reason 任意 |
| DB-006 (users) | read | role 確認（`admin` であること） |

## AuditLog 書き込み

| フィールド | 値 |
| --- | --- |
| `action` | `publish` |
| `actor_id` | `viewer.user_id` |
| `actor_role` | スナップショット（`admin` を含む） |
| `target_proposal_id` | パス引数 |
| `before_status` | `approved` |
| `after_status` | `published` |
| `reason` | リクエストの reason または NULL |
| `policy_agreement_id` | NULL |
| `created_at` | `now()` |

`reason` 必須要否: **任意**（Q-019 暫定）。

## 認可拒否時の挙動

| 拒否シナリオ | HTTP | logger `403_reason` |
| --- | --- | --- |
| cookie なし | 401 | `not_authenticated` |
| cookie あるが role に `admin` を含まない（reviewer / user / auditor） | 404 | `insufficient_role` |
| Origin 不一致 (CSRF, B-2) | **403** | `cross_site` |

副作用なし（`BR-AUDIT-03`）。reviewer が呼んでも 404 を返し AuditLog 記録なし。

## バリデーション規約

- Zod（暫定）
- 順序:
  1. ボディスキーマ（reason 任意）→ 400
  2. authorize（role に `admin` を含む）→ 404
  3. proposal 取得 → `status='approved'` 検証 → 422
  4. CAS UPDATE → 409

## エラーコード

| HTTP | コード | 用途 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 入力検証 |
| 401 | `UNAUTHENTICATED` | 未認証 |
| 404 | `NOT_FOUND` | role 不足 / 不存在 |
| 409 | `CONFLICT` | 楽観ロック |
| 422 | `BUSINESS_RULE_VIOLATION` | `status != 'approved'` |
| 500 | `INTERNAL_ERROR` | 想定外 |
