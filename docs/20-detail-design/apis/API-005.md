# API-005 — returnProposal（差し戻し server function）

## 概要

担当中の `reviewer` または `admin` が `in_review` の提案を `returned` に遷移させる mutation。reason 必須（`BR-REVIEW-01`）。投稿者は再提出（API-009）で同 proposal を再度 `submitted` に戻すことができる。

## エンドポイント

```
POST /v1/proposals/{id}/return
```

## 認可

- **レベル**: `authenticated`
- **必要ロール**: `reviewer` または `admin`
- **リソース所有者一致**: **不要 (B-3 撤回)**。reviewer / admin であれば assignee に関わらず判定可（API-004 と同じ方針、要件 REQ-003 / BR-REVIEW-* に従う）
- **CSRF 検証**: Origin / Sec-Fetch-Site=same-origin（NFR-006）
- **レート制限**: MVP 対象外（Q-013 暫定）

## リクエスト

### パスパラメータ

| 名前 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string (uuid v7) | yes | `status='in_review'` 前提 |

### ボディ

```json
{
  "reason": "本文に個人名が含まれている可能性があるため、該当箇所の修正をお願いします",
  "expected_version": 2
}
```

#### スキーマ

| フィールド | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `reason` | string | **yes** | 1〜4000 文字、trim 後 1 文字以上 |
| `expected_version` | integer | yes | CAS 用 |

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Cookie` | yes | 認証 cookie |
| `Origin` | yes | 同一オリジン |
| `Sec-Fetch-Site` | yes | `same-origin` |

## レスポンス

### 200 OK

```json
{
  "proposal_id": "01HXYZ...",
  "status": "returned",
  "version": 3,
  "audit_log_id": "01HXYZ-al..."
}
```

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `proposal_id` | string | yes | 対象 ID |
| `status` | string | yes | `"returned"` |
| `version` | integer | yes | +1 |
| `audit_log_id` | string | yes | append された AuditLog ID |

### 4xx / 5xx

| ステータス | アプリコード | 状況 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | reason 空 / 文字数超過 |
| 401 | `UNAUTHENTICATED` | cookie なし |
| 404 | `NOT_FOUND` | role 不足 / 自身が assignee でない / proposal 不存在 |
| 409 | `CONFLICT` | 楽観ロック失敗 |
| 422 | `BUSINESS_RULE_VIOLATION` | `status != 'in_review'` |
| 500 | `INTERNAL_ERROR` | 想定外 |

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-003 (proposals) | write (UPDATE, CAS) | `WHERE id=? AND version=expected_version AND status='in_review'` で `status='returned'`、`assignee_id=NULL`、`updated_at=now`、`version+1`。**B-3 撤回**: assignee_id 一致条件は CAS から削除 |
| DB-004 (audit_logs) | append (INSERT) | reason 必須。後続の API-009 (resubmit) で `action=return` の件数 = 差し戻し回数（REQ-006） |
| DB-006 (users) | read | role 確認 |

## AuditLog 書き込み

| フィールド | 値 |
| --- | --- |
| `action` | `return` |
| `actor_id` | `viewer.user_id` |
| `actor_role` | スナップショット |
| `target_proposal_id` | パス引数 |
| `before_status` | `in_review` |
| `after_status` | `returned` |
| `reason` | NOT NULL（投稿者が再編集時に参照、SCR-006 / API-013 で表示） |
| `policy_agreement_id` | NULL |
| `created_at` | `now()` |

`reason` 必須要否: **必須**。reason は投稿者本人が再提出時に参照する（API-013 のレスポンスに含まれる）。

## 認可拒否時の挙動

| 拒否シナリオ | HTTP | logger `403_reason` |
| --- | --- | --- |
| cookie なし | 401 | `not_authenticated` |
| role が `user` のみ / `auditor` | 404 | `insufficient_role` |
| ~~`assignee_id != viewer.user_id`~~ **撤回 (B-3)**: assignee 一致は要求しない、reviewer/admin であれば誰でも判定可 | — | — |
| Origin 不一致 (CSRF, B-2) | **403** | `cross_site` |

副作用なし。
