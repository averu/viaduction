# API-019 — login（モック認証ログイン server function、公開バイパス）

## 概要

cookie + 環境変数の許可リストでセッションを確立するモック認証ログイン（REQ-015 / UC-018）。**公開バイパス対象**（認可ヘルパースキップ、UC-013 認可境界の対象外）。許可リスト外の入力は 401。成功時は `HttpOnly` / `Secure` / `SameSite=Lax` 以上の認証 cookie を発行（NFR-006）。

## エンドポイント

```
POST /v1/auth/login
```

## 認可

> **公開バイパスと CSRF 検証は独立（m-06 整理）**: 「公開バイパス」は authorize ヘルパー（role / owner 一致の判定）をスキップする概念であり、CSRF 検証（Origin / Sec-Fetch-Site）とは **完全に独立した防御層**。CSRF 検証は **全 mutation / 認証境界エンドポイントで一律に適用**（公開バイパス対象でも例外なし、NFR-006）。

- **レベル**: `public`（公開バイパス対象）
- **必要ロール**: なし（このエンドポイント自体が認証境界の入口）
- **公開バイパス**: **対象**（authorize ヘルパーをスキップ）
- **CSRF 検証**: Origin / Sec-Fetch-Site=same-origin（NFR-006）。違反は 403 で拒否（CSRF 対策）。**公開バイパス対象でも CSRF 検証は実施**（m-06 整理）。
- **レート制限**: MVP 対象外（Q-013 暫定。将来的にはブルートフォース対策のため検討すべき箇所）

## リクエスト

### パスパラメータ

なし。

### クエリパラメータ

なし。

### ヘッダ

| 名前 | 必須 | 説明 |
| --- | --- | --- |
| `Origin` | yes | 同一オリジン（NFR-006 CSRF） |
| `Sec-Fetch-Site` | yes | `same-origin` |

### ボディ

```json
{
  "user_identifier": "U1",
  "role_request": null
}
```

#### スキーマ

| フィールド | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `user_identifier` | string | yes | 不透明 ID（任意文字列）。最大 128 文字。許可リストの key と照合 |
| `role_request` | string \| null | no | 任意の role 指定（`user` / `reviewer` / `admin` / `auditor` / それらの CSV）。許可リストの roles の **部分集合** であれば許可、完全に外れていれば 401。null の場合は許可リストの全 roles を採用 |

> `role_request` の用途: 同一ユーザが複数ロールを兼任する場合に、テストや E2E で「reviewer 視点で動作確認したい」等の切替を可能にする（学習目的、GOAL-05 / GOAL-06）。本番運用では使用しない想定。

## レスポンス

### 200 OK

```json
{
  "user_id": "U1",
  "display_name": "山田 太郎",
  "roles": ["reviewer"],
  "session_expires_at": 1746363600000
}
```

#### スキーマ

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `user_id` | string | yes | 確立されたセッションの user_id（DB-006 `id` と一致） |
| `display_name` | string \| null | no | 表示名（DB-006 `display_name`）。**表示専用 — レスポンス body / 画面表示は可、logger / エラーメッセージには出さない**（NFR-005 PII 配慮、DB-006 不変条件 3 と整合、M-2 確定） |
| `roles` | array of string | yes | 確立された roles（OR 合成、`BR-AUTHZ-01`） |
| `session_expires_at` | integer | yes | セッション有効期限（Unix epoch millis） |

#### Set-Cookie ヘッダ

```
Set-Cookie: session=<opaque-cookie-value>; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=3600
```

- `HttpOnly`: 必須（NFR-006）
- `Secure`: 本番環境では必須、ローカル開発は省略可（Phase 5 で環境別設定）
- `SameSite=Lax`: 必須（NFR-006）
- `Max-Age`: 3600 秒（1 時間、暫定。Phase 5 で確定）

### 4xx / 5xx

| ステータス | アプリコード | 状況 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | `user_identifier` 欠落 / 形式不正 / `role_request` の値不正 |
| 401 | `UNAUTHENTICATED` | 許可リスト外の `user_identifier`、または `role_request` が許可リストの roles の部分集合でない |
| 403 | `CSRF_DENIED` | Origin 不一致 / Sec-Fetch-Site != same-origin（公開バイパスでも CSRF は適用） |
| 500 | `INTERNAL_ERROR` | 想定外（許可リスト読み込み失敗等） |

```json
{
  "error": {
    "code": "UNAUTHENTICATED",
    "message": "ログインに失敗しました"
  }
}
```

> エラーメッセージは「許可リストにあるかどうか」を漏らさない統一文言にする（タイミング攻撃対策の最低線）。

## 副作用 / DB アクセス

| DB | 操作 | 備考 |
| --- | --- | --- |
| DB-006 (users) | read | `findById(user_identifier)` で許可リスト同期済みのユーザを取得。許可リスト外なら 401 |

> **DB write なし**: ユーザレコードは許可リストパース時にのみ生成される。本 API は認証 cookie の発行のみ。

## ログ出力

- 成功時: `user_id_hash` / `roles` / `session_expires_at` のみ。`display_name` は出さない（NFR-005）
- 失敗時: `403_reason=not_authenticated` または `cross_site` を logger に出力

## バリデーション規約

- Zod（暫定）
- `user_identifier`: 1〜128 文字
- `role_request`: enum CSV（許容値: `user` / `reviewer` / `admin` / `auditor`）

## エラーコード

| HTTP | コード | 用途 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 入力検証 |
| 401 | `UNAUTHENTICATED` | 許可リスト外 / role 不一致 |
| 403 | `CSRF_DENIED` | CSRF 検証失敗 |
| 500 | `INTERNAL_ERROR` | 想定外 |

## 認可拒否時の挙動

公開バイパス対象のため authorize 層のチェックはなし。代わりに以下:
- 許可リスト外 → 401（`403_reason=not_authenticated`）
- CSRF 違反 → 403（`403_reason=cross_site`）
- 副作用なし
