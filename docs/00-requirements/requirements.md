## 5. 機能要件 (REQ-XXX)

各要件は次の形式で書く。

```
### REQ-001 — <短い名前>
- 概要: <1〜2 行>
- 受入基準:
  - [ ] <観測可能な条件>
  - [ ] ...
- 関連ユーザストーリー: US-01
- 仕様（未確定事項）: <あれば、?? と質問内容>
```

### REQ-001 — 登録済アカウントでログインできる
- 概要: 利用者がメールアドレスとパスワードを入力してログインし、セッショントークンを取得できる。
- 受入基準:
  - [ ] 正しい資格情報でログインに成功し、セッショントークンが返る
  - [ ] 誤った資格情報では 401 を返す
- 関連ユーザストーリー: US-01
- 仕様（未確定事項）:

> 上記は **書式の参考としての例**。実プロジェクトでは要件に応じて書き換え・追加してください。
> 雛形だけが欲しい場合は次のスタブを使ってください（コードブロック内なので trace の対象外）：
>
> ```
> ### REQ-XXX — <短い名前>
> - 概要:
> - 受入基準:
>   - [ ]
> - 関連ユーザストーリー:
> - 仕様（未確定事項）:
> ```

## 6. 非機能要件 (NFR-XXX)

各非機能要件は次の形式で書く。性能・可用性・セキュリティ・運用性などを含める。

### NFR-001 — パスワードはハッシュで保管する
- カテゴリ: セキュリティ
- 目標値: argon2id (memory>=64MB, parallelism>=2) を使い、平文パスワードを保管しない
- 計測方法: 静的解析でパスワードを暗号化せずに DB に保存する箇所が無いことを確認
- 関連 REQ: REQ-001
