# interview-requirements

要件発見 (Phase 0) または要件精査 (Phase 1) で、素材に **抜け** や **曖昧** がある状態を検出し、質問形式で記録する Skill。要件を勝手に補完しない。

## いつ使うか

- 要件素材に抜け・曖昧が疑われる状態
- ユーザが「不明点を質問にして」「不確かな箇所を洗い出して」と言ったとき
- 要件レビュア Subagent が「BLOCKER は無いが MAJOR が多い」と判定した後

## 動作

1. `$ARGUMENTS` の解釈：
   - 空または `discovery` → `docs/00-discovery/*.md` を対象に `07-open-questions.md` へ追記
   - `refinement` → `docs/01-requirement-refinement/*.md` を対象に `02-ambiguity-review.md` へ追記
2. `Agent(subagent_type=requirement-interviewer)` を呼ぶ。
3. Subagent が次の項目について **書かれていないこと** を抽出：
   - アクター / 入力 / 出力 / 例外 / 数値 / 期日 / 制約
4. **質問形式** で対象ファイルに追記。
5. 質問は **YES/NO・数値・列挙のいずれかで答えられる粒度** にする。
6. 結果を提示して「これらの質問が回答されたら `/refine-requirements` に進みます」と案内。

## 必ず守ること

- 自分で **回答を埋めない**。Claude が「〜が一般的なので〜とします」のような断定をしない
- 質問は **回答すべき相手** を必ず明記する（不明なら `未割当`）
- 既存の `Q-XXX` と意味的に重複する場合は **新規追加せず**、該当行に「再確認」を付記
- 100 件以上は出さない。重要度の高い 30 件に絞る

## 質問テンプレート

```markdown
| Q-XXX | <質問本文> | <回答すべき相手> | <起票日> | <期限> | open | (空欄) |
```

カテゴリ例：

- **アクター不明**: 「この機能を使うのは管理者か一般ユーザか、両方か？」
- **数値未定**: 「P95 レスポンスの目標値は何ミリ秒か？」
- **境界不明**: 「同時操作の上限は何件を想定するか？」
- **例外不明**: 「決済が失敗した場合、商品予約はどうなるか？」
- **法令確認**: 「個人情報を保管するなら GDPR / 改正個人情報保護法のどちらを準拠とするか？」

## 出力フォーマット

```markdown
## インタビュー結果

- 抽出した不足情報: 12 件
- うち BLOCKER 級: 2 件
- 既に open になっている同種質問: 3 件（重複扱い）

## 追加した Q-XXX
- Q-010: 認証失敗時のロック期間（@PO）
- ...

## 次のアクション
- 質問が回答されるまで、対象 RC を `needs-clarification` ステータスに保つ
```

## 完了条件

- 対象ファイルに新しい `Q-XXX` 行が 1 件以上追加されている
- 既存の `Q-XXX` を書き換えていない

## 関連

- 前段: `discover-requirements`
- 次段: `refine-requirements`
- 補完: `review-requirements` (より厳密なレビュー)

## やってはいけないこと

- 既存の `IDEA-XXX` `PROB-XXX` `RC-XXX` を **書き換える**
- `### Status` を変更する
- 自分の推測を回答として書き込む
- `02-requirements/**` のファイルに触れる
